# convgen

`convgen` 是 Go 编译期结构体转换生成器。业务代码只写 `//convgen:` 注释，
生成阶段完成字段、类型与转换函数校验，输出单文件 `conv_gen.go`。

生成的代码没有反射、没有运行时依赖，也不包含 `panic`。

最低支持 Go 1.22。

## 安装

从源码安装：

```sh
go install .
# 或只构建到当前目录
go build -trimpath -o bin/convgen .
```

## 使用

在 Go 源文件中声明转换：

```go
package controller

import (
	"example.com/proj/internal/api"
	"example.com/proj/internal/db"
)

//convgen: -s db.User -d api.User -fn apiUserFull
//    -map DisplayName=Name, Avatar=Profile.Avatar
//    -conv CreatedAt=toTime, UpdatedAt=toTime
//    -deep Tags, Metadata
//    -ignore InternalID
```

运行：

```sh
convgen ./...
```

同目录生成 `conv_gen.go`。同包多个声明聚合到一个文件，函数按名称字典序排列；
重复运行结果逐字节幂等。

## 参数

| 参数 | 必填 | 多值 | 说明 |
|:---|:---|:---|:---|
| `-s` | 是 | 否 | 源类型：`Type`、`pkg.Type` 或完整 import path |
| `-d` | 是 | 否 | 目标类型 |
| `-fn` | 否 | 否 | 函数名；省略时自动推导 |
| `-type` | 否 | 否 | `val_val`（默认）、`val_ptr`、`ptr_val`、`ptr_ptr` |
| `-map` | 否 | 是 | `目标字段=源字段`，源字段支持 `A.B` |
| `-conv` | 否 | 是 | `目标字段=表达式`；`$` 代表源字段，见下节 |
| `-ignore` | 否 | 是 | 跳过目标字段 |
| `-deep` | 否 | 是 | 对 slice/map/pointer 做一层深拷贝 |

多值参数使用逗号分隔，逗号后可带空格。`-map` 与 `-conv` 可以同时作用于同一
目标字段：先由 `-map` 选源字段，再由 `-conv` 加工。`-ignore` 不能与
`-map`、`-conv`、`-deep` 同字段使用；`-conv` 与 `-deep` 互斥。

`-conv` 可以重复出现，适合按字段或转换边界分行；同一声明中的多个 `-conv`
会合并到同一张字段映射。同一参数内的目标字段不能重复；`-map`、`-ignore`、
`-deep` 同样禁止重复。单值参数 `-s`、`-d`、`-fn`、`-type` 也只能出现一次。

### 转换表达式

`-conv` 的值是 Go 表达式模板，`$` 会在生成时替换为当前源字段：

```go
//convgen: -s Record -d User -fn UserFromRecord
//    -conv Name=strings.TrimSpace
//    -conv Role=roleName
//    -conv CreatedAt=$.UTC().Format(time.RFC3339)
```

- 没有 `$` 时按单参数函数调用处理，生成 `fn(src.Field)`。单参数函数可以省略
  `($)`：`-conv Name=strings.TrimSpace` 与 `-conv Name=strings.TrimSpace($)` 等价。
- 需要固定参数、链式调用或多次使用源字段时，用 `$` 写完整表达式，例如
  `strings.ReplaceAll($, " ", "-")`。
- `$` 可以出现多次；字符串字面量中的 `$` 不替换。
- 包限定符优先使用当前包已 import 的别名；未 import 时按同名 import path 尝试加载，
  例如标准库 `strings`、`time`。生成文件会自动补齐 imports。
- 表达式只要求是单个 Go 表达式；逗号、括号和字符串字面量由解析器按层级切分。
- 表达式最终经 `go/format` 输出，函数内部 panic 不在生成器承诺范围内。

## 声明规则

- 首行 `//convgen:` 必须位于行首注释，可有前导空白。
- 续行使用 `//` 加至少两个空格或一个 tab，后续内容拼接为一个逻辑声明。
- 空行、普通代码行或下一条 `//convgen:` 会结束当前声明。
- 输出路径固定为同包目录下的 `conv_gen.go`，不支持自定义。
- 生成文件首行为 `// Code generated by convgen. DO NOT EDIT.`，再次扫描时跳过。

## 生成契约

- 每个函数上方回显标准化声明和 `// Source: <相对 go.mod 的路径>`。
- `ptr_val` 的 nil 输入返回零值；`ptr_ptr` 返回 `nil`。
- `-deep` 对 nil slice/map/pointer 返回 `nil`；对 `*T` 只复制一层值。
- 每个目标字段必须被赋值或被 `-ignore` 显式跳过；否则生成前一次性列出所有未赋值字段。
- 跨包非导出目标字段无法赋值，也必须使用 `-ignore`。
- 生成失败不写半成品；`./...` 会聚合包错误后统一退出非零。
- 声明与规划错误以 `file:line:` 开头，可在终端或 IDE 中直接点击跳转。
- 函数增删提示写入 stderr，格式为 `[pkg] + name` / `[pkg] - name`。

较新的 Go `gofmt` 会改写函数文档注释，因此回显块与函数之间保留一个空行。
这保证 `//convgen:` 与固定 4 空格续行可逐字保留，同时通过 `gofmt`。

## 限制

- 仅支持非泛型结构体；源包与目标包不能同名。
- 嵌套 `-map` 路径禁止指针中间段。
- `-conv` 表达式必须能解析为 Go 表达式；包或符号不存在时生成前报错。
- 扫描跳过生成文件、测试文件、`vendor/`、`.git/`、`testdata/` 和
  `node_modules/`。
- 已有 `conv_gen.go` 首行不是生成标记时拒绝覆盖。

## CI

建议在业务仓库中提交生成文件并检查漂移：

```sh
convgen ./...
git diff --exit-code -- '*conv_gen.go'
go build ./...
```

## 开发与提交

首次 clone 后启用仓库内的 DCO 提交钩子：

```sh
make hooks
```

每个提交必须包含与作者身份一致的 `Signed-off-by`。改写历史后重新补签，并运行：

```sh
git rebase --signoff origin/main
DCO_BASE=origin/main make dco-check
```

依赖变化后刷新第三方许可清单：

```sh
make license-update
make license-check
```
